# Phase 7: Historical Format Log Tables

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Every task is tests-first and ends with a focused test and commit.

**Goal:** Render logarithm tables in the historical proportional layout used by printed 1950s-era log tables (see `https://undergroundmathematics.org/exp-and-log/calculators1950/assets/logtables.pdf`), served and viewed in the browser, where the user chooses the **N resolution** (which fixes the table decade) and the **log precision**.

**Architecture:** A new historical-format renderer consumes the existing integer-only `LogTable` rows and reshapes them into the proportional sub-column layout. It runs inside the existing Flask + htmx `webapp.py` browser surface; no new calculation engine or floating point is introduced. Range selection is derived from N resolution and is always a fixed decade (`1–10`, `10–100`, `100–1000`, …) with the upper bound excluded.

**Tech Stack:** Python 3.14+, standard-library `html`, pytest, Flask + htmx (already present), integer-only engine (`integer_log.py`).

## Global Constraints

- Every displayed value comes from the existing integer-only `calculate_row` / `scaled_to_text` path; no `math.log`, no floats, no reusing a rounded row to compute another row.
- The N resolution fixes the decade: resolution `r` ⇒ table covers `10**r`–`10**(r+1)` with `10**(r+1)` **excluded**. Resolution `0` ⇒ `1–10` (10 excluded), `1` ⇒ `10–100` (100 excluded), `2` ⇒ `100–1000` (1000 excluded), and so on.
- Log precision is the existing `fractional_digits` count; the user picks it and it controls mantissa width.
- All user-controlled text is HTML-escaped; generated bytes are UTF-8 and newline-stable within a render call.
- The historical layout is a faithful structural reproduction (proportional rows, argument sub-columns, mean-difference columns), not a claim of reproducing a specific typeface.

## Scope and non-scope

In scope:

- A resolution + log-precision form that produces a historical-format table in the browser.
- The proportional layout: rows keyed by the leading digits of N, a base argument column, and mantissa sub-columns for each trailing unit. No interpolation/mean-difference (proportional parts) table is generated — the reader calculates interpolation themselves from the shown mantissas.
- Decade range is fixed and upper-bound-exclusive per the user's stated rule.

Out of scope (documented extension points, must not be implied as done):

- Reproducing exact typefaces or page ornaments from a specific printed book.
- Bar/characteristic notation; modern decimal notation is used for mantissas.
- PDF output (Phase 6 owns that).

## Public symbols

- `class HistoricalConfig`: immutable; `resolution: int` (≥ 0), `log_precision: int` (≥ 1), `base: int = 10`. Owns validation and the decade-range derivation only.
- `decade_range(resolution: int) -> tuple[int, int]`: returns `(10**resolution, 10**(resolution+1))`; the upper bound is the stop (exclusive) for the generator.
- `build_historical_table(config: HistoricalConfig) -> HistoricalTable`: constructs the proportional layout from an integer-only `LogTable`.
- `class ProportionalRow`: `argument: str`, `columns: tuple[str, ...]` (mantissa sub-column text).
- `class HistoricalTable`: `config: HistoricalConfig`, `rows: tuple[ProportionalRow, ...]`.
- `render_historical_html(table: HistoricalTable, title: str | None = None) -> str`: returns an escaped, deterministic HTML fragment for the browser.

## Decade and layout rules

1. Resolution `r` fixes the decade `D = [10**r, 10**(r+1))`. The generator computes `log_base(N)` for each integer `N` in `D` with `10**(r+1)` excluded.
2. In the proportional layout each row is keyed by the **leading significant digits** of N (the "argument"). For resolution `r` the argument ranges over the integers from `10**r` up to `10**(r+1) - 1`; within a row the sub-columns are the unit steps (e.g. for `r=1`, row "10" covers 100–109, row "11" covers 110–119, …). The exact sub-column count is `10` per row and matches the printed convention.
3. Each cell shows the mantissa digits of `log_base(N)` truncated/rounded to `log_precision` fractional digits via `scaled_to_text`. The leading characteristic is shown once per row (as in the PDF) rather than repeated in every cell.
4. No mean-difference / proportional-parts interpolation table is produced. Only the argument column and the 10 mantissa sub-columns per row are shown; interpolation is left to the reader, who can compute it from the shown mantissas.
