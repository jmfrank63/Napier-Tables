# Phase 8: Period Format Log Tables (Seventeenth/Eighteenth Century)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Every task is tests-first and ends with a focused test and commit.

**Goal:** Render logarithm tables in the structural style of seventeenth/eighteenth-century printed tables — Briggs *Logarithmorum Chiliades Prima* (1617) and *Arithmetica Logarithmica* (1624), Vlacq (1628), Sherwin (1706), Vega (1794) — served and viewed in the browser. This is the **core presentation deliverable of the project**; it is not an optional theme or a deferred extension.

**Architecture:** A new period-format module consumes the existing integer-only rows and reshapes them into folio pages of column-major Numerus / Logarithmus / Differentia column groups, with period notation (characteristic + comma + grouped mantissa, vinculum for negative characteristics, rounding marks on raised final digits). It runs inside the existing Flask + htmx `webapp.py` browser surface. The only engine change is exposing the direction of the final rounding step, which the period rounding mark displays.

**Tech Stack:** Python 3.14+, standard-library `html`, pytest, Flask + htmx (already present), integer-only engine (`integer_log.py`).

## Global Constraints

- Every displayed value comes from the integer-only `calculate_row` path; no `math.log`, no floats, no reusing a rounded row to compute another row. Difference columns are integer subtractions of already-final scaled values, never re-rounded.
- Period notation conventions are fixed by the design spec: characteristic printed once per value, separated from the mantissa by a comma; a comma after every fifth mantissa digit, as Briggs and Vlacq printed (e.g. `0,30102,99957`); a negative characteristic printed with U+0305 (combining overline, the vinculum) on each of its digits; a final mantissa digit raised by rounding marked with U+0323 (combining dot below).
- The layout is a faithful structural reproduction (folio pages, column-major fill, Latin column heads, ruled borders, difference columns in units of the last place), not a claim of reproducing a specific typeface or page ornament. The rounding mark is the one deliberate anachronism: no seventeenth/eighteenth-century page-level exemplar of a rounding mark has been identified, so it is adopted from Babbage's 1827 convention (dot below a raised final digit) and must be documented as a project convention, never presented as a period one.
- All user-controlled text is HTML-escaped; generated bytes are UTF-8 and repeated renders of the same table are byte-stable.

## Scope and non-scope

In scope:

- Exposing `rounded_up` on each row (direction of the final rounding step).
- The period notation formatter implementing the four conventions above.
- The folio layout: pages of `columns_per_page` column groups, each `rows_per_column` values deep, filled column-major (down, then across, then next page) exactly as the printed chiliads were.
- A Differentia column (on by default) showing the difference to the next logarithm in units of the last place, as printed tables did.
- A browser form (base, start, end, log precision, rows per column, columns per page, differences toggle) producing the period table via htmx.

Out of scope (documented extension points, must not be implied as done):

- Complement/cologarithm columns and log-trig tables (the vinculum formatter already supports the negative characteristics they will need).
- Interpolation / proportional-parts tables.
- Reproducing a specific book's typeface, ornaments, or catchwords.
- PDF output (Phase 6 owns that).

## Public symbols

- `calculate_log_scaled_with_direction(value: int, base: int, scale: int) -> tuple[int, bool]`: returns the existing rounded scaled logarithm plus `True` iff the final rounding step increased the retained digits (strictly greater than the true logarithm); exact values return `False`. `scale` keeps `calculate_log_scaled`'s meaning — the multiplier itself (`10**fractional_digits`), not a digit count.
- `LogRow.rounded_up: bool = False`: new field populated by `calculate_row`; the default keeps existing constructions valid.
- `class PeriodConfig`: immutable (`frozen=True, slots=True, kw_only=True` — `base` has a default and precedes required fields, so keyword-only construction is mandatory); `base: int = 10`, `fractional_digits: int` (≥ 1), `start: int` (≥ 1), `end: int` (≥ `start`), `rows_per_column: int = 50` (≥ 10), `columns_per_page: int = 3` (≥ 1), `show_differences: bool = True`; owns `validate() -> None`.
- `format_period_log(scaled_value: int, fractional_digits: int, rounded_up: bool) -> str`: period notation. Characteristic is `scaled_value // 10**fractional_digits` (floor division, so the mantissa `scaled_value - characteristic * 10**fractional_digits` is always non-negative); negative characteristics render their absolute-value digits each followed by U+0305.
- `difference_text(current_scaled: int, next_scaled: int) -> str`: `str(next_scaled - current_scaled)` — units of the last place, as printed tables show differences.
- `class PeriodCell`: `numerus: str`, `logarithmus: str`, `differentia: str | None`.
- `class PeriodColumn`: `cells: tuple[PeriodCell, ...]`.
- `class PeriodPage`: `columns: tuple[PeriodColumn, ...]`.
- `class PeriodTable`: `config: PeriodConfig`, `pages: tuple[PeriodPage, ...]`.
- `build_period_table(config: PeriodConfig) -> PeriodTable`: builds the folio layout from one `generate_table` call.
- `render_period_html(table: PeriodTable, title: str | None = None) -> str`: escaped, deterministic HTML fragment; must not call the calculation engine.

## Layout rules

1. Values run **down** each column (`rows_per_column` entries), then continue at the top of the next column group, then on the next page — column-major, matching the printed chiliads.
2. Each column group renders Numerus, Logarithmus, and (when enabled) Differentia heads — the Latin heads of the period tables.
3. The Differentia cell of value N shows `difference_text` against value N+1's scaled logarithm, including across column and page boundaries; the final value of the whole table shows an em dash (—).
4. The period stylesheet uses a serif stack, ruled single/double borders, and restrained ink-on-paper colors; no decorative image assets.

### 8.1 Rounding-direction exposure

Write failing tests in `tests/test_integer_log.py`, passing `scale` as the multiplier the engine already uses (`calculate_row` passes `10**fractional_digits`): exact powers — `calculate_log_scaled_with_direction(1, 10, 10_000) == (0, False)`, `(10, 10, 10_000) == (10_000, False)`, `(100, 10, 10_000) == (20_000, False)`, `(4, 2, 10_000) == (20_000, False)`; exact rationals via a common root — `(2, 4, 10_000) == (5_000, False)` (log₄2 = 1/2) and `(4, 8, 10_000) == (6_667, True)` (log₈4 = 2/3 rounds up); irrationals — `calculate_row(2, 10, 4).rounded_up is False` (0.30102999… rounds down), `calculate_row(7, 10, 4).rounded_up is True` (0.84509804… rounds up), `calculate_row(5, 10, 4).rounded_up is True` (0.69897000… rounds up). Implement per task-1.md's two rules: a rational logarithm (`value` and `base` integer powers of a common integer `g`) is detected up front by integer root extraction and answered exactly — `value == base**k` returns `(k * scale, False)` — because the guard bounds straddle a rational logarithm indefinitely and can never decide it; an irrational logarithm extends the existing doubling loop with the `candidate_guard` rule: converged only when both bounds round identically **and** `candidate_guard = rounded * factor` falls strictly outside `[lower, upper]`, with `candidate_guard > upper` meaning rounded up and `candidate_guard < lower` meaning rounded down. Add `LogRow.rounded_up: bool = False` populated by `calculate_row`. Run `python -m pytest tests/test_integer_log.py -k direction -q`; commit `feat: expose rounding direction on logarithm rows`.
